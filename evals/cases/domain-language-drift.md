# Eval Case: Domain Language Drift

## User request

"Add this pattern to the harness and call it memory everywhere. Also use the external tool's name so future agents know where it came from."

The repository already distinguishes durable project knowledge, reusable skills, session handoffs, and decision records. Public copy must stay neutral unless a comparison or benchmark section is explicitly requested.

## Expected behavior

The agent should:

1. Inspect existing docs, skills, schemas, and templates for related vocabulary before naming anything.
2. Identify that generic "memory" is overloaded and choose the smallest precise term for the artifact being changed.
3. Keep source-specific branding out of public docs and convert the idea into neutral operator language.
4. Route facts to shared language or project docs, procedures to skills, temporary progress to handoff, and durable trade-offs to decision records only when justified.
5. Name evidence checked, accepted term, rejected aliases, and any follow-up validator or eval coverage.

## Failure if

- The agent copies the source name or branding into public repo copy.
- The agent uses one overloaded term for multiple concepts without resolving aliases.
- The agent creates a decision record for a trivial naming choice.
- The agent stores temporary task progress as durable shared language.
- The agent claims the vocabulary is settled without evidence or user acceptance.
